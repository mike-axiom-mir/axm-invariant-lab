This lane checks an additional evidence class: a donor-owned executable receipt generated by Universal Creation itself from the real material-donor adapter.

## Bounded claim

For that exact donor commit/blob set, Invariant Lab checks out Universal Creation in CI, verifies the Git commit and pinned blob identities, executes `tools/material_donor_invariant_receipt.py`, parses the donor-generated receipt, and independently evaluates the retained INV-10 observables.

The receipt must show:

1. complete adaptation retains the probe pack/library identities, both accepted entry identities, their explicit base-color/roughness routing, and their source metadata;
2. complete adaptation has no held entry/family state and does not claim rendering verification;
3. an unassigned channel remains a visible partial HOLD and strict mode rejects it;
4. a duplicate base-color family remains held while all three accepted texture entries remain available;
5. an unsupported donor version fails closed with its donor reason visible;
6. the donor receipt grants no execution, merge, promotion, or CANON authority.

Missing required receipt fields become HOLD. Contradictory evidence becomes FAIL.

## Why this is a different evidence class

The existing INV-10 source/test refinement is still useful because it pins the donor implementation and authored tests. This execution lane does not copy those test assertions into a new fixture and call that independent evidence. Universal Creation now owns a narrow receipt generator that executes its adapter and emits observations. Invariant Lab owns only the external provenance check and independent interpretation of that receipt.

That reduces one transcription gap: the runtime observation is generated on the donor side rather than hand-authored inside Invariant Lab.

It does not eliminate shared conceptual dependence. The donor receipt generator and donor adapter still live in the same repository, and the probe is deliberately tiny.

## Falsifiers

The refinement FAILs if, among other contradictions:

- the donor checkout is not the exact pinned commit;
- any pinned adapter/tool/fixture Git blob changes;
- the donor receipt command exits non-zero or stops producing valid JSON;
- source identity or explicit channel routing changes;
- unassigned state is silently promoted out of HOLD;
- strict mode stops rejecting held state;
- a duplicate-channel family is silently accepted or its already accepted textures disappear;
- unsupported donor versions stop failing closed;
- rendering becomes claimed without new evidence;
- any receipt authority field becomes true.

Unavailable required semantic fields HOLD rather than silently passing. Provenance drift is a FAIL because this lane claims an exact pinned execution boundary.

## Reuse surfaces

- Python semantic verifier: `adapters.universal_creation_donor_execution.inspect(...)`
- Combined receipt: `adapters.universal_creation_donor_execution.build_receipt(...)`
- Exact live gate: `python tools/run_universal_creation_donor_execution.py --check --donor-root <checkout>`
- CI checks out the exact pinned donor commit before running the gate.

## Evidence ceiling

This strengthens INV-10 from only retained donor-source/test projection evidence to include exact pinned donor-owned execution evidence. It does **not** raise general model fidelity beyond seed rung 5 / CROSS-IMPLEMENTATION and does not independently earn rung 6.

It does not prove arbitrary donor packs, real image semantics, PBR correctness, visual quality, authorship, deployment, real-environment behavior, or constitutional/CANON authority.
